WALL has 24 chronological chapters and the prologue, 35 community atlas entries, 20 Kabbalah readings, 20 calendar observances, eight responsibility records and 408 source catalogue entries. The four locales are Turkish, English, Hebrew and Azerbaijani. The Rabin case in v0.8.6 distinguishes the Tel Aviv rally and mourning, Yigal Amir’s opposition to the Oslo talks, and Clinton’s response. Luna reviewed the claims and translations against ACC08A–C.

v0.8.7 retains failed writes in the open session and can export them or retry saving. Simulated quota failures showed a localized warning in the game, study room and settings in all four languages at 320 CSS pixels and 200% text size. The browser route exported Hebrew draft text and progress while writes were blocked, then retried and reopened both after reloading. Luna reviewed the pending-write and recovery path. Local Chromium took six half-second samples per version while a movement key stayed pressed at the settled edge. The callback counts were 30 in each v0.8.6 sample and zero in each v0.8.7 sample. Reversing direction still moved the character.

Simulated 30, 60 and 120 Hz frame schedules gave equal one-second travel, parked at the same boundary and resumed when the direction reversed. In six local headless Chromium runs per version at 320 × 700, median times from navigation to visible game were 179 ms and 184 ms in fresh contexts (v0.8.6 and v0.8.7), and 71 ms and 58 ms after reloading. The observed ranges overlap in both comparisons.

The Windows Setup and Portable executables and the Linux AppImage launched in their install checks. The Android emulator played in portrait and landscape, used synthetic controller events and resumed the saved chapter after relaunch. Browser controller mapping tests used simulation.

The save schema is still 1. The build records identify the exact source commit, locale list, save schema, and SHA-256 revisions for the plan, lesson content, catalogue and all packaged game inputs. The Pages response and the records extracted from the released ZIP, HTML, APK and AppImage match. Two builds with different commit metadata but the same inputs produced the same game fingerprint. Desktop staging uses the checked-out tag’s commit even when the triggering workflow SHA differs.

Open plan acceptance for 1.0: external history, language and first-time learner reviews and physical phone/controller testing, including performance on target hardware. The APK uses preview signing and Windows binaries are unsigned. The integration lacks write access to the repository’s Actions secrets for durable Android signing. Prior preview saves can be exported and merged through Settings.
