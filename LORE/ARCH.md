# Architecture

- Start: index.html and start.js display the reference-led Fragaria loader and call start() after browser initialization.
- Runtime: game.js owns the chronological chapter state, focus and movement, source and study panels, and local progression. Completion is keyed by chapter ID. v0.1 saves remain readable.
- Art: world.js caches scenery, advances the visitor from animation frame time and only redraws active movement or changed scenes.
- Content: content.js assembles the chronological campaign. scenes.js and sequences.js supply the stage models and ordering tasks. The six four-chapter evidence decks load when their disclosure opens. In completed chapters, transfer.js loads a separate eight-chapter deck when requested and stores practice results and drafts under wall.transfer.<chapter>.*. The study room loads separate calendar, atlas, diaspora, Kotel, language, Kabbalah, and everyday-life modules. catalogue.js loads the public docs/SOURCES.tsv on demand.
- Local progress: save-data.js combines the wall.progress.v1 snapshot with per-chapter wall.completed.v1 records and pending writes. The snapshot records the last scene and can include the visitor’s position and facing from world.js. Movement saves at rest, at the scene boundary, or when the page becomes hidden. Completion records survive competing snapshot writes. Export and import keep schema 1 and merge chapter progress while retaining existing drafts and preferences. The exhibition keeps its source choices and wall.journal notes. Study drafts and wall.appearance.v1 stay in local storage.
- Testing: tests/browser.cjs exercises the full route with Playwright. WALL_BROWSER_ENGINE selects Chromium, Firefox or WebKit. The browser compatibility workflow installs each engine on GitHub runners. The installed smoke workflow separately launches the AppImage, both Windows binaries and an Android API 35 emulator.
- Deployment: scripts/build.mjs exports static files. The live Pages site uses the branch source in gh-pages. scripts/publish-pages.sh builds a clean main revision, updates that branch by fast-forward and records the source commit in build.json. The Actions workflow deploys directly when the repository publishes through the workflow source.
